# Independent preset sync

`node server/preset-sync/index.mjs` serves the local browser on HTTP8792 and native clients on HTTPS9447. Both bind127.0.0.1. The health relay9443 is independent. Native clients must validate TLS using the existing app CA; no TLS bypass is provided.

The TLS certificate and key have no default: set `PITIN_PRESET_TLS_CERT` and `PITIN_PRESET_TLS_KEY` (for local development, `npm run dev-tls` creates a pair in `server/.dev-tls/` and prints the two lines to set them). Preferences are kept outside this project in `../.setup/pitin-preset-sync/preferences.json`. Startup restricts the preference directory and existing files to the current Windows user. Port overrides: `PITIN_PRESET_HTTP_PORT`, `PITIN_PRESET_TLS_PORT`. No credential is printed.

`createPresetSyncService({storeFile=null,tls,now=Date.now,browserHandler,kakaoRestKey=process.env.KAKAO_REST_KEY ?? null,fetchImpl=globalThis.fetch})` synchronously returns `{httpServer,httpsServer,engine,close}` without listening. `close()` is asynchronous and releases the writer lock. `storeFile=null` is ephemeral for isolated tests. Default browser assets are `web/continuity` plus shared fonts; an optional handler replaces static routing only.

The exact persisted object is `{schemaVersion:1,presets,selectedId,defaultId,autoDefaultOnRest}`. `store.mjs` exports `preferences(state)` and `validatePreferences(data,defaults)` for migration. Obtain defaults from a fresh `ContinuityEngine().getState()`. Invalid data fails startup. Session secrets, feeling, plans, observations and events never enter this file. Every successful command commits preferences before replying; failure rolls engine state, clock, simulated physical values and request history back.

An exclusive `.lock` file prevents another writer. Normal SIGINT/SIGTERM shutdown releases it. Force-killing Node or rebooting can leave it behind. Inspect the startup failure, then explicitly run `node server/preset-sync/index.mjs --recover-lock`. Recovery requires a valid stored PID and an OS `ESRCH` result proving that process is absent; live, inaccessible or malformed PIDs are refused. It only removes the lock and never changes preferences. PID reuse safely refuses recovery. The next normal invocation starts the service.

## 쉬어 갈 곳 (place proposal and place search)

**Proposal (shared state).** Command `propose_place` (approved phone only; the car and the local web page get 403) with payload exactly `{place:{name,address,lat,lon}}`: `name` 1~40 chars after trimming, `address` 0~120 chars, `lat`/`lon` both `null` or both numbers inside Korea (lat 33~39, lon 124~132), rounded to 4 decimals. It sets `state.devices.vehicle.place` to `{id:'place-<uuid>',name,address,lat,lon}`; a new proposal replaces the old one. The vehicle command `clear_place` with payload exactly `{id}` sets it back to `null` only when the id still matches, otherwise 409 `PLACE_CHANGED` with the latest state. The car starts any 길안내 on its own screen. The field starts as `null`, lives only in memory and never enters the preferences file, so older stores load unchanged.

**Search (Kakao proxy).** `POST /api/preset-sync/v1/places/search`, HTTPS only, approved `phone` only (others 403), body exactly `{query,kind}`: `query` 1~40 chars after trimming without control characters, `kind` one of `park|cafe|bookstore|sauna|other` (else 400). The server calls Kakao Local keyword search with `query` and `size=15` (plus `category_group_code=CE7` for `cafe`), `Authorization: KakaoAK <key>` and a 5 s timeout, and answers `{places:[{id:'kakao:<id>',name,address,lat,lon,category}],sync}` with at most 15 places (items without finite in-Korea coordinates are dropped). Errors: 503 `PLACES_UNAVAILABLE` when no key is set, 502 `PLACES_FAILED` on upstream non-2xx, timeout or bad JSON, 429 `SEARCH_LIMIT` after 30 searches per session per rolling minute.

Set the REST key with the `KAKAO_REST_KEY` environment variable before starting the service; it stays on this server and is never sent to the phone.

Privacy rules: the phone sends only the query text. No coordinates are accepted from the phone or sent to Kakao (so the server does not handle the phone's location). Neither the query, the key nor the upstream body is logged or echoed in an error. A place proposal carries only name, address and point: no visit counts, favourites or history.

Run `node --test tests/preset-sync.test.mjs` and `npm test`. TLS integration tests generate a fresh process-local key/certificate through `tests/fixtures/ephemeral-tls.mjs`, trust only that certificate, and bind ephemeral loopback ports. No private test key is bundled. Actual browser/native UI integration, runtime ACL inspection, and port8792/9447 startup are separate parent-owned validation.
